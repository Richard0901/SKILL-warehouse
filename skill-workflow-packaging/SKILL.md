# Skill 工作流封装

## 这是什么

一个 skill 不该只是 markdown 笔记。真正可用的 skill，至少要回答：

1. 它解决什么问题
2. 何时触发
3. 不该何时触发
4. 需要哪些输入
5. 输出什么结果
6. 适合内联执行还是隔离执行

这个 skill 讲的是：如何把一个工作流包装成 OpenClaw 里真正可用的技能。

## 在 OpenClaw 里何时使用

1. 你想把一套操作步骤沉淀成 skill
2. 你发现某类任务经常重复出现
3. 你在整理本地 skills 目录
4. 你想让 skill 更容易被正确命中

## 核心原则

1. skill 是工作流包，不是宣传文案。
2. `whenToUse` 要写触发语言，不要写空话。
3. listing 文本必须有预算。
4. 复杂流程要考虑隔离执行。
5. skill 调用语义要明确，不能只在回答里提到 skill 名字。

## 一个好 skill 至少应包含

1. 名称
2. 描述
3. 适用场景
4. 不适用场景
5. 核心步骤
6. 与当前工具链的映射
7. 常见失败模式
8. 可产出物

## OpenClaw 里的实战建议

1. 如果 skill 明显对应某类请求，描述里要把触发词写清楚。
2. skill 列表中的描述要短，正文再展开。
3. 对复杂任务，skill 应明确是否建议用 `sessions_spawn` 隔离执行。
4. skill 应说明会用哪些 OpenClaw 工具，而不是只讲概念。
5. 多个相近 skill 要做边界区分，避免重叠命中。

## 常见失败模式

1. `whenToUse` 太泛，什么都像它。
2. 描述太长，导致列表成本大于收益。
3. skill 里全是理论，没有本地工具映射。
4. 本该隔离执行的流程硬塞进主会话。
5. 说“使用某 skill”，但实际没有真正执行对应工作流。

## 你可以产出的东西

1. 一份 skill 模板
2. 一份 skill 命名与触发规范
3. 一份“内联执行 vs 隔离执行”的判定表
